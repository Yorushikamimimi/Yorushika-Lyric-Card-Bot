## 3. `board.json` 数据契约

### 顶层字段
- `schemaVersion`: `1`
- `generated_at`: ISO 时间戳
- `sources`: `{catalog, vault_cards_found, ledger_rows, manifest_items, fav_candidates}`
- `enums`: `{stages: [6态], dispositions: [6态], platforms: [{id, short, name}×4]}`
- `totals`: 全盘统计（不含 `drawer` 抽屉）：`{ready_to_publish, in_progress, published_posts, queued_fav, reserve, leftover, dropped, total_items}`
- `groups`: 4 个区块（`active` 正在扩充、`ready` 已齐活待排发、`archive` 已收官历史与搁置、`drawer` 底层角色库）
- `directions[]`: 17 个方向，含 `id, group, name, tagline, cover, cards_hint, planned_cards?, counts`
  - `counts` 内含封面卡必显 **4 个核心数字**：`ready_to_publish`（已过可发）、`in_progress`（制作待核）、`published_posts`（已发帖数）、`queued_fav`（收藏待扩），以及拆分 `reserve / leftover / dropped / total_items`
- `planned_cards[]`: `鹿102`–`鹿118` 共 17 张待排卡的蓝图、关联条目 `linked_items`、预览 `thumbs` 与当前 Vault 实时状态 `vault_status`
- `items[]`: 全部单张素材（382 项），关键字段：
  - 归属：`id, direction, batch, title, live, song, tc, card, planned_card, source`
  - **轴 A（制作与审核进度 6 态）**：`stage`（`收藏待排` / `制作中·待领` / `待我初核` / `待你终核` / `返修中` / `已通过`），辅以 `ai_reviewed, user_reviewed, revision_round, vault_status, versions`
  - **轴 B（发布处置去向 6 态）**：`disposition`（`待排发` / `已入发帖夹` / `已发布` / `备选留存` / `边角料` / `已淘汰·搁置`），辅以 `disposition_reason, post_folder`
  - **四平台状态**：`platforms` 为 `{xhs, dy, x, ig}`，每项 `{status: "published"|"ready"|"unpub"|"skip", url, date, title, stats}`
  - **媒体路径**：`media`（主展示图/GIF，均相对 `output/`）与 `alt_media[]`（原图对照/MP4 等）

## 4. `qiye/src/console/` 后端需要做的三件事

1. **静态文件白名单放行（`suiming.py`）**：
   - 当前 `suiming.py` 的 `/yoru/<path>` 只放行 `pixel-*` 目录与 `manifest.json` 点名的文件，且 `FILE_LIMIT = 4_000_000`、后缀不含 `.mp4`。
   - 新看板的 `media` 与 `alt_media` 涵盖 `publish-20261118/lib-*`、`emoji-alt-20261123`、`live-photo-real-20261124`、`live-luanru-20261124`、`live-compare-20261124`、`zense2024-x-20261125` 以及 `live-first-look` / `auto-review-*` / `user-captures` 等收藏原图路径。
   - **建议做法**：参照 `_listed_files(root)` 的机制，只放行 `board.json` 中所有 `directions[].cover`、`items[].media`、`items[].alt_media` 显式点名的相对路径（仍保留 `resolve()` 防 `..` 与符号链接校验），允许 `.png/.gif/.jpg/.jpeg/.mp4`，并将单文件上限放宽到 `20_000_000`（部分高清 GIF 超过 4MB）。
   - **样例模式隔离**：在 `fixtures/` 下放极小脱敏样例或无真路径时安全降级提示，绝不越权读取真实目录以外的路径。
2. **新增只读与重建/写回接口**：
   - `GET /api/yoru-board`：在 `--archive`（真实档案）模式下读取 `Yorushika-Lyric-Card-Bot/output/publish-20261118/board/board.json`；或按需调用 `build_board.py` 刷新后返回。
   - `POST /api/yoru-board/disposition`：接收 `{updates: [...]}`，严格校验字段白名单、6 态枚举及 `已淘汰·搁置` 必填原因，仅在 `--archive` 模式下调用 `build_board.py --apply-updates <tmp>` 原子写入 `board_edits.json` 并返回最新 `board.json`（与 `suiming.py` `favorites.json` 同级安全标准）。
3. **保留既有页面职责不变**：
   - 原 `#assets` 如需加跳转入口指向新看板或合并视图均可；保留原有 `manifest.json` 141 项历史清单只读兼容性，不动 `build_manifest.py`。
